# 수의사 인증 심사 및 동물병원 등록·연동 확장 로드맵 (추후 진행)

> **상태:** 보류 (추후 확장 프로세스로 체크)  
> **관련 관리자 경로:** `/admin/verifications`

---

## 1. 배경 및 보류 사유

- 기존에 잡아두었던 `수의사 검증 · 질병` 구상은 실제 서비스 방향(`수의사 자격 검증` + `소속 병원 연동`)과 맞지 않으며, `pet_diseases` 역시 현재 건강 수첩(`pet_journeys` · `pet_histories`) 중심으로 전환된 상태입니다.
- 특히 현재는 **유저가 제출한 수의사 면허번호가 실제 유효한 면허인지 진위를 확인하는 검증 프로세스**가 갖춰져 있지 않으므로, 해당 기능은 추후 인증 체계 정리 후 확장 구현하기로 보류합니다.

---

## 2. Phase A — 유저 수의사 인증 신청 및 관리자 심사

### 2-1. 선결 과제 (진위 확인 프로세스)
- 수의사 면허번호만 입력받았을 때 실제 수의사 여부를 검증할 수 있는 수단 확정 필요
  - 후보 1: 공적 조회 API / 면허 진위 확인 연동 여부 검토
  - 후보 2: 면허증 사본(이미지/PDF) 또는 재직증명서 첨부 후 관리자 수동 검수

### 2-2. 유저 제출 Flow
- 수의사 인증 신청 시 입력 항목:
  - **수의사 면허번호** (필수)
  - **소속 병원** (선택 — 직접 입력 또는 등록된 병원 검색 선택)
  - (확장 시) 면허 증빙 자료

### 2-3. 관리자 심사 Flow (`/admin/verifications`)
- 인증 신청 대기 목록 확인 (`신청자 정보`, `면허번호`, `소속 병원`, `제출 일시`, `상태`)
- 관리자 검수 후 처리:
  - **승인 (`APPROVED`):** 해당 회원을 `VET` 역할로 전환(`users.role = 'VET'`), `vet_license_number` / `vet_hospital_name`(및 병원 매핑) 반영, 감사 로그 기록
  - **반려 (`REJECTED`):** 반려 사유 입력 및 유저 안내, 감사 로그 기록

---

## 3. Phase B — 동물병원 등록 시스템 및 수의사 프로필 연동

### 3-1. 동물병원 등록 시스템 (`vet_hospitals` 등)
- 병원을 독립 엔티티로 등록·관리할 수 있는 구조 구축
- 주요 저장/표시 정보:
  - **병원 이름**
  - **병원 위치** (주소, 상세 위치, 지도 좌표 등)
  - **취급 동물** (강아지, 고양이, 토끼, 햄스터, 기니피그, 친칠라, 기타 특수동물 등)
  - **운영시간** (요일별 진료시간, 휴무일, 야간/응급 진료 여부 등)
  - 연락처 / 홈페이지 / 소개 등 부가 정보

### 3-2. 수의사 ↔ 병원 연동 및 프로필 노출
- 등록된 **병원**과 인증된 **수의사(`VET`)** 계정을 연결(소속/원장/진료의 등)
- **수의사 회원 프로필 페이지 확장:**
  - 기존 수의사가 작성한 게시글/답변 내역뿐만 아니라,
  - **해당 수의사가 운영 중이거나 재직 중인 병원 정보 카드**(병원명, 위치, 취급 동물, 운영시간 등)를 함께 표시
